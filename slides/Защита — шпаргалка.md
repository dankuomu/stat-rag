1. `data/logs/answer_log.parquet` — одна строка: конфигурация, найденное, ответ, F1.

## Вопросы и ответы

**Логи «готовые», а вы их сами получили?** В пяти заданных датасетах нет прогонов RAG с параметрами и ответами, только вопросы, документы и эталоны. Логи получены своим прогоном по сетке параметров; без этого нет регрессии «качество ~ параметры».

**Почему Вилкоксон, а для бинарных — Мак-Немар?** F1 бимодален (Шапиро — Уилк p < 1e-29), один вопрос во всех конфигурациях — парные ранговые тесты. Нулевые разности отбрасываются (zero_method wilcox). Для 0/1-метрик (полнота SQuAD, правильность) ранговый тест не нужен, там Мак-Немар.

**Как p = 0,77 доказывает плато?** Не доказывает — это и учтено. Дан бутстреп-интервал парной разности F1 между k = 10 и k = 5: −0,003 [−0,024; 0,018] на HotpotQA. Вывод — прирост больше 0,018 отвергается. Эквивалентность ±0,02 по TOST формально не проходит на тысячные, это написано в отчете.

**Пересечение вопроса с документом — по какому документу? Есть ли оно у реальной системы?** По эталонному. Поэтому оно используется только как свойство вопроса в регрессии и корреляциях, а в классификатор правильности не входит. Классификатор видит только то, что есть у системы: настройки, длину вопроса, оценки ретривера, уверенность ридера.

**Что итерации делают на SQuAD?** Нужен один абзац, он находится с первого шага. Полнота к шагу 4 ниже одношаговой: 0,970 против 0,987 (Мак-Немар, p_Holm = 0,028). F1 падает с ростом контекста в обоих режимах (−0,024 и −0,015), а на одном шаге режимы по F1 не различаются — итерации сами F1 не снижают. Пейдж односторонний, падение ловит Фридман.

**Почему comparison хуже bridge?** Из выборки убраны ответы yes/no — это 31 % comparison в train (5 481 из 17 456), у bridge их нет. Остались вопросы «какой из двух» — ридер выбирает не тот объект. Тип распределен по уровням ровно, с поправкой на уровень эффект −0,14 F1, p = 0,005. Вывод только про такие вопросы.

**Что такое «динамика по итерациям» у вас?** Шаги итеративного поиска: к запросу дописывается ответ с прошлого шага, добавляются 3 новых фрагмента. Контроль — обычный поиск того же объема. Версий системы во времени в данных нет.

**Почему ридер, а не LLM?** Ответы в выбранных датасетах — отрезки текста, EM и F1 корректны без LLM-судьи, прогон воспроизводим на ноутбуке. Ограничение: ридер обучен на SQuAD, F1 на SQuAD завышен.

**Почему HotpotQA из train?** В dev все вопросы уровня hard, а уровень сложности — фактор гипотезы H4. Ридер на HotpotQA не обучался.

**Почему плотный поиск лучше BM25, если в BEIR наоборот?** BEIR — вне домена обучения. e5 дообучалась на MS MARCO и NQ, предобучалась на Википедии; пересечение с нашими корпусами не исключено, вывод относится к этим корпусам.

**Что главное?** Внутри датасета настройки объясняют около 1 % разброса F1, вопрос — 60–68 %. Сравнивать конфигурации RAG нужно парно на одних вопросах.

**H1 на SQuAD: Фридман p = 0,049 — а поправка?** С Холмом на четыре омнибусных теста H1 он незначим. Решение опирается на парную разность гибрид минус BM25: +0,026 [0,007; 0,045], Вилкоксон p_Holm = 0,031. Эффект мал, вдвое меньше, чем на HotpotQA, — так и написано.

**«Прирост больше 0,018 отвергается» — на каком уровне?** Это верхняя граница двустороннего 95 % интервала, то есть односторонний уровень 97,5 %.
